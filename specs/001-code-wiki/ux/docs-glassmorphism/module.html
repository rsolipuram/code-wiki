How It Works

The authentication flow is split into three coordinated phases: credential verification, session creation, and token issuance. Each phase is isolated in its own file to keep responsibilities clear and unit-testable.

Login Flow

authenticate_user() in login.py receives a username and plaintext password. It fetches the stored bcrypt hash from the Database Layer, calls bcrypt.checkpw() to verify the password, then calls create_session() and tokens.py to produce a signed JWT and a server-side session record.

# Simplified login flow (login.py)
def authenticate_user(username: str, password: str) -> AuthResult:
    user = db.find_user(username)
    if not bcrypt.checkpw(password.encode(), user.password_hash):
        raise InvalidCredentialsError()
    session_id = create_session(user.id)
    token = generate_token(user, session_id)
    return AuthResult(token=token, session_id=session_id)

Middleware Flow

AuthenticationMiddleware in middleware.py intercepts every protected HTTP request. It extracts the Bearer token from the Authorization header, calls verify_token() to validate the signature and expiry, then checks the Redis session store to confirm the session is still active before forwarding the request.

Configuration

The authentication module reads the following environment variables. These should be set in your deployment environment or .env file:

# JWT settings
JWT_SECRET=your-256-bit-secret-here
JWT_ACCESS_EXPIRY=900         # 15 minutes in seconds
JWT_REFRESH_EXPIRY=604800     # 7 days in seconds

# Bcrypt cost factor (12–14 recommended for production)
BCRYPT_ROUNDS=12

# Redis session store
REDIS_URL=redis://localhost:6379
SESSION_PREFIX=auth:session:
